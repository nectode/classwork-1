# Контрольные вопросы

**1. Зачем добавлять папку PHP в переменную PATH и как проверить, что PHP установлен?**
PATH — список папок, в которых Windows ищет исполняемые файлы. Если добавить `C:\php`, команда `php` будет работать из любой папки в CMD, без указания полного пути. Проверка: в новом окне CMD выполнить `php -v` (покажет версию) и `php --ini` (покажет, какой php.ini загружен).

**2. Какой командой запускается встроенный сервер PHP и как указать другой порт или корневую папку?**
`php -S localhost:8000`. Другой порт: `php -S localhost:8080`. Корневая папка: ключ `-t`, например `php -S localhost:8000 -t C:\projects\filemanager`.

**3. Почему форма загрузки не работает без enctype="multipart/form-data"?**
Без этого атрибута браузер отправляет только имя файла как обычное текстовое поле, а не его содержимое. Тип `multipart/form-data` разбивает запрос на части и позволяет передавать бинарные данные, поэтому без него `$_FILES` остаётся пустым. Форма также должна использовать метод POST.

**4. Какие ключи содержит массив $_FILES['userfile'] и что хранится в tmp_name?**
Ключи: `name` (исходное имя), `full_path`, `type` (MIME-тип от браузера), `tmp_name`, `error` (код ошибки), `size` (размер в байтах). В `tmp_name` хранится путь к временному файлу на сервере, куда PHP сохранил загрузку; он удаляется после окончания скрипта.

**5. Чем move_uploaded_file() отличается от copy()?**
`move_uploaded_file()` сначала проверяет, что файл действительно загружен через HTTP POST, и только потом перемещает его (исходный временный файл не остаётся). `copy()` такой проверки не делает и просто копирует любой файл, поэтому злоумышленник мог бы подсунуть путь к системному файлу.

**6. Чем отличаются директивы upload_max_filesize и post_max_size? Какое значение должно быть больше и почему?**
`upload_max_filesize` — предел размера одного файла, `post_max_size` — предел всего POST-запроса (все файлы + поля формы). `post_max_size` должен быть больше, так как в запрос кроме файла входят служебные данные и поля формы, а при нескольких файлах он должен вмещать их суммарный размер.

**7. Что произойдёт с массивами $_POST и $_FILES, если запрос больше post_max_size?**
Оба массива окажутся полностью пустыми, а в журнале появится предупреждение. Поэтому код ошибки в `$_FILES` проверить нельзя: превышение определяют по пустому `$_FILES` при `CONTENT_LENGTH > 0`.

**8. Почему upload_max_filesize нельзя изменить через ini_set()?**
К моменту запуска скрипта запрос уже принят и обработан сервером, а файл уже получен. Поэтому директиву задают заранее: в php.ini или ключом `-d` при запуске сервера.

**9. Для чего при удалении и сохранении файлов используется basename()?**
`basename()` отбрасывает из имени путь, оставляя только само имя файла. Это защищает от обхода каталогов: без неё через `?file=../index.php` можно было бы удалить файл сайта, а при сохранении записать файл за пределы папки uploads.

**10. Почему нельзя разрешать загрузку файлов с расширением .php?**
Загруженный `.php`-файл лежит в папке на сервере, и если открыть его в браузере, сервер его выполнит. Злоумышленник сможет запустить произвольный код (веб-шелл) и получить контроль над сайтом и сервером.
